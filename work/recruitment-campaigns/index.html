Recruitment campaigns and SMS opt-in

Campaign builds, exclusion logic and a compliant text-message opt-in for a healthcare staffing team.

Work
Marketing Cloud Growth and Data Cloud build
Platform
Marketing Cloud, Data Cloud
Stack
Marketing Cloud Growth, Data Cloud, Salesforce, SMS
Client
Private, by agreement

In one paragraph

A healthcare staffing team needed recurring outreach to several candidate audiences without emailing people who had already replied or been placed, and wanted to add text messages without breaking consent rules. I mapped audiences and exclusions as rules, fed Data Cloud from web and CRM sources so segments stay current, built the campaigns, and wrote an SMS opt-in flow around keywords and consent records.

The challenge

A staffing team needed outreach to several audiences without emailing people who had already replied or been placed, and wanted to add text messages without breaking consent rules.

Approach

  • Mapped audiences and exclusions before building, so suppression was a rule rather than a manual list.

What was built

  • Campaign builds with exclusion logic across audiences.
  • An SMS opt-in flow with keyword handling and consent recording.
  • Email templates, a statement of work, operating procedures and build documentation.
  • Data Cloud ingestion and configuration fixes feeding the segments.

Outcome

The team runs recurring campaigns from documented procedures, with text messaging added on a consent trail that stands up to review.

Background

Staffing outreach is high volume and repetitive: the same kinds of candidates, the same kinds of roles, week after week. The failure mode is not sending too little, it is sending to the wrong people: someone who replied yesterday, someone already placed, someone who opted out. Text messaging raises the stakes because consent is regulated and auditable.

The problem in detail

Exclusions were being handled as manual lists, which drift. Segments depended on exports, which go stale. There was no text channel, and adding one without a consent trail would have created risk rather than reach.

How the work was done

Audiences and exclusions were mapped before anything was built, so that suppression became a rule in the segment rather than a list someone maintains. Data Cloud was fed from web and CRM sources, so segments update as the data does. The SMS opt-in flow was written around keywords and consent records, then tested end to end with real phones before launch.

What was delivered

Campaign builds with exclusion logic across audiences. An SMS opt-in flow with keyword handling and consent recording. Email templates, a statement of work, operating procedures and build documentation so the team can run campaigns without me. Data Cloud ingestion and configuration fixes feeding the segments.

Results

The team runs recurring campaigns from documented procedures, with text messaging added on a consent trail that stands up to review.

What this means for your team

  • Make suppression a rule inside the segment, not a list outside it.
  • Feed segments from live sources. An exported list is wrong the day after it is exported.
  • Test consent flows with real phones and record the results before the first send.

Questions about this project

What is Marketing Cloud Growth?

Salesforce's marketing automation edition built on the core platform and Data Cloud, used here for email and SMS campaigns driven by Data Cloud segments.

How is SMS consent handled?

Through an opt-in flow that recognises keywords, records consent on the person's record with a timestamp, and honours stop requests, so every send can be traced to a consent event.

Why did Data Cloud need configuration fixes?

Ingestion from web and CRM sources had to be mapped correctly for the segments to resolve. Fixing that configuration was part of making the segments trustworthy.
