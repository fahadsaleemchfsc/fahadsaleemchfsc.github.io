Sales reporting and goal dashboard

A custom Lightning component for goal tracking, plus the weekly reporting leadership runs on.

Salesforce Lightning component and reporting
Platform
Salesforce, Reporting
Stack
Salesforce, Lightning Web Components, Apex, CRM Analytics

In one paragraph

Reps could not see progress against target without opening several reports, and the weekly leadership numbers were compiled by hand. I built a Lightning Web Component for the Salesforce home page from the designer's file, with goal attainment, a period picker and metric cards, kept the calculations in Apex with tests, deployed from source control, and standardised the weekly report so the same figures come out every time.

Background

Standard Salesforce reports answer questions when someone runs them. A goal dashboard on the home page answers the one question a rep has every morning without them asking it. Leadership, meanwhile, wants a weekly set of numbers that do not change depending on who compiled them.

The problem in detail

Goal attainment lived in several reports a rep had to open and mentally combine. The weekly leadership report was assembled by hand from reports and dashboards, which took time and introduced variation.

How the work was done

The component was built as a Lightning Web Component from the designer's file so it matches the brand exactly. Calculations live in Apex classes with unit tests, which keeps the component fast and the logic testable. Everything was deployed from source control rather than changed in the org by hand. The weekly report was standardised: the same reports and dashboards, the same figures, written into the team's sheet.

What was delivered

A home-page component with goal attainment, a period picker and metric cards. Supporting Apex classes with tests, deployed from source control. A weekly sales report built from reports and dashboards and written into the team's sheet.

Results

Reps see where they stand on login, and leadership gets the same weekly numbers without anyone compiling them.

What this means for your team

  • Put the daily question on the home page. Reports are for the other questions.
  • Keep calculations in Apex with tests, so the component is a view and the logic is verifiable.
  • Standardise the weekly report before automating it. Automation of an inconsistent process produces consistent nonsense.

Questions about this project

What is a Lightning Web Component?

Salesforce's framework for building custom user-interface components with standard web technologies, which can be placed on Lightning pages such as the home page.

Why Apex for the calculations rather than the component?

Apex runs on the server with access to data and can be unit-tested. The component stays light and the numbers are produced the same way every time.

Can the weekly report be fully automated?

Yes. Once the figures and sources are standard, the report can be produced on a schedule and written to the sheet without a person compiling it.
